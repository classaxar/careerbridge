Project Overview

CareerBridge is a LinkedIn-inspired full-stack professional networking platform designed for three user groups: Internship seekers, Full-time professionals, and Senior citizens (55+). It also includes a separate Recruiter Portal where companies can post jobs and manage applications.

💡 What makes this project unique?

  • Three distinct user modes in one app — Intern, Professional, Senior
  • Real frontend ↔ backend communication via REST API
  • Recruiter jobs posted from the backend appear live on the job seeker side
  • Custom TradingView-inspired dark UI theme with CSS variables
  • No UI library (no Tailwind, no Bootstrap) — all CSS written from scratch

Technology Stack

React 19 Main UI framework. All pages are React functional components. Used hooks: useState, useEffect, useContext, useCallback. Frontend
Vite Build tool and development server (replaces Create React App). Provides HMR (Hot Module Replacement) and fast build. Build Tool
React Context API Global state management (no Redux). Used to share: active tab, user mode (intern/pro/senior), notification count across all components. State Mgmt
Vanilla CSS All styling written in custom CSS files. Uses CSS variables (custom properties), Flexbox, CSS Grid, animations (keyframes), media queries for responsiveness. Styling
Node.js + Express.js Backend REST API server running on port 5001. Handles CRUD for jobs and applications. Uses ES Modules (import/export syntax). Backend
In-Memory Store (db.js) JavaScript arrays acting as a database. Pre-seeded with sample jobs and applications. No MongoDB or SQL needed. Data Layer
Lucide React Open-source icon library. Used for all icons (Briefcase, Users, Bell, Search, etc.) as React SVG components. Icons
Google Fonts – Inter Primary font: Inter (weights 300–900). Monospace font: JetBrains Mono for code/numbers. Loaded via @import in CSS. Typography
UUID (npm package) Generates unique IDs (v4 format) for each job posting and application in the backend. Utility
CORS (npm package) Cross-Origin Resource Sharing middleware. Allows the React frontend (port 5173) to make API calls to Express backend (port 5001). Security
Vite Proxy Configured in vite.config.js to forward all /api/* requests from the frontend to http://localhost:5001 during development. Config

Backend REST API Reference

The backend runs as a separate Node.js process on port 5001. Vite proxies all /api/* requests from the React frontend to this server automatically during development.

Jobs API — /api/jobs

GET /api/jobs Returns all jobs. Optional query params: ?type=internship, ?recruiterId=r1 READ
POST /api/jobs Creates a new job. Body: { title, company, type, location, stipend/salary, tags, ... } CREATE
PUT /api/jobs/:id Updates a job by ID (used to pause/activate or edit). Merges body fields into existing object. UPDATE
DELETE /api/jobs/:id Removes a job from the in-memory array by ID. DELETE

Applications API — /api/applications

GET /api/applications Returns all applications. Filter by ?jobId=, ?recruiterId=, ?status= READ
POST /api/applications Submit an application. Body: { jobId, name, email, portfolio, coverNote }. Also increments job.applicants counter. CREATE
PATCH /api/applications/:id Updates only the status field: pending → shortlisted → accepted / rejected UPDATE

Key CSS Concepts Used

CSS Custom Properties :root { --accent-green: #26a69a; } — all colors, spacing, radii defined as variables. mode-senior class overrides them for senior mode.
CSS Grid Feed page 3-column layout, jobs card grid, applicant card grid — all using CSS Grid with responsive auto-fill.
CSS Flexbox Used in almost every component for row/column alignment (navbar, cards, buttons, chat layout).
@keyframes Animations fadeInUp (page transitions), shimmer (loading skeleton), pulse-dot (live indicator), float (hover effect), ticker-scroll (scrolling bar).
CSS Transitions Used on all interactive elements: buttons (translateY hover lift), sidebar width, skill bars, card borders, color changes.
Backdrop Filter backdrop-filter: blur(16px) on Navbar creates the glassmorphism frosted glass effect.
CSS ::after Pseudo-element Active tab underline indicator drawn with ::after pseudo-element (no extra HTML needed).
Media Queries @media (max-width: 700px), @media (max-width: 900px) — responsive layouts switch from multi-column to single column.
CSS Gradient Text background-clip: text; -webkit-text-fill-color: transparent — Used on the landing page hero title for colored gradient text.
Position: sticky Navbar and sidebars use position:sticky so they stay visible during scroll without JavaScript.

Likely Professor Questions & Model Answers

Q1 What is React and why did you use it instead of plain HTML/JS?
React is a JavaScript UI library that uses a component-based architecture and a virtual DOM. I used it because: (1) it lets me break the UI into reusable components (Navbar, JobCard, etc.), (2) state changes automatically re-render only the affected part of the page — no manual DOM manipulation, and (3) hooks like useState and useEffect make data fetching and state management clean and predictable.
Q2 What is the difference between useState and useEffect?
useState stores reactive data inside a component. When you call setState, the component re-renders. useEffect runs side effects (like API calls, subscriptions) after the component renders. Example: I use useState to store the fetched jobs array, and useEffect to call fetch('/api/jobs') when the component mounts or when the category tab changes.
Q3 What is React Context API and why did you use it instead of Redux?
Context API is React's built-in global state solution. I created AppContext with useContext to share the active tab, user mode (intern/professional/senior), and notification count across all components without prop drilling. I chose Context over Redux because this project doesn't need complex state transforms — Context is simpler and requires zero extra libraries.
Q4 What is a REST API and how does your frontend connect to the backend?
A REST API uses HTTP methods (GET, POST, PUT, PATCH, DELETE) and URLs to perform CRUD operations. My Express server exposes /api/jobs and /api/applications endpoints. The React frontend calls these using the browser's fetch() API. Vite is configured to proxy all /api/* requests to localhost:5001, so the frontend doesn't need to know the backend's port.
Q5 What is CORS and why do you need it?
CORS (Cross-Origin Resource Sharing) is a browser security policy that blocks requests between different origins (domains or ports). Since React runs on port 5173 and Express on port 5001, the browser would normally block the API call. I installed the cors npm package in Express and configured it to allow requests from localhost:5173.
Q6 Why didn't you use a database like MongoDB?
I used in-memory JavaScript arrays (db.js) as the data store. This was a deliberate choice for the project submission because it requires zero setup, works immediately on any machine, and demonstrates the API architecture clearly. The data resets on server restart, which is fine for a demo. To make it production-ready, I would replace the arrays with MongoDB + Mongoose, which would only require changing db.js without touching any routes.
Q7 What is Vite and why is it better than Create React App?
Vite is a modern build tool that uses ES Modules directly in the browser during development, making the dev server start nearly instant (under 300ms vs 10-30s for CRA). It has native HMR (Hot Module Replacement) which updates only the changed module — not the whole page. It also has a smaller config, better performance, and is the current industry standard replacing CRA.
Q8 Explain the role-based architecture of your app.
The app has two completely separate UIs — Job Seeker and Recruiter — managed by a role gate in main.jsx. When the app loads, it shows the RoleSelect landing page. If the user clicks "Recruiter", the RecruiterPortal component is rendered (with its own sidebar, dashboard, and pages). If they click "Job Seeker", the main AppProvider + App component renders (with the top navbar and 5-page navigation). Both share the same backend API, so data is synchronized between them.
Q9 What CSS concepts are most important in your project?
The most important: (1) CSS Custom Properties for the design token system enabling the 3 user modes. (2) CSS Grid for the 3-column feed layout and card grids. (3) @keyframes for fadeInUp page transitions, skeleton loading shimmer, and the live pulse dot. (4) Flexbox for component-level alignment. (5) Backdrop-filter: blur for the glassmorphism navbar effect.
Q10 How do recruiter job postings appear on the job seeker side?
When a recruiter fills the Post Job form and clicks submit, the frontend makes a POST request to /api/jobs on the Express server. The server adds the new job to its in-memory jobs[] array and returns the created job. When a job seeker switches to the Jobs page or changes the category tab, a useEffect triggers a GET /api/jobs?type=internship call — which now includes the recruiter's newly posted job — and renders it as a card.

How to Run the Project

Step 1 — Open two terminal windows in the project folder

# Terminal 1 — Start the Backend API Server
npm run server
# → Server starts at http://localhost:5001

# Terminal 2 — Start the Frontend Dev Server
npm run dev
# → App opens at http://localhost:5173

Step 2 — Open http://localhost:5173 in the browser

  • The Role Select landing screen appears
  • Click Job Seeker to see the main platform (Feed, Jobs, Network, Messages, Profile)
  • Click Recruiter to see the recruiter portal (Dashboard, Post Job, Manage, Applicants)

Step 3 — Test the integration

  • Go to Recruiter → Post a Job → fill the form → click Post
  • Switch back to Job Seeker → click Jobs → see the new job appear in the list
  • Click Apply → fill form → Submit
  • Switch to Recruiter → Applicants tab → see the application with Accept/Reject buttons
